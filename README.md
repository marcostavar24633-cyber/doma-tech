# DOMA TECH — серверная версия 3.0

Полноценный стартовый проект интернет-магазина посудомоечных машин:
- публичная витрина;
- серверный каталог на SQLite;
- защищённый вход администратора;
- добавление, редактирование и удаление товаров;
- загрузка изображений;
- приём заявок покупателей;
- управление статусами заявок;
- ограничение частоты входа и отправки заявок;
- сессии с HttpOnly/SameSite cookies и SQLite-хранилищем;
- базовые security headers.

## Требования
- Node.js 20 или новее
- npm

## Локальный запуск
1. Распакуйте архив.
2. В терминале перейдите в папку проекта.
3. Установите зависимости:
   `npm install`
4. Скопируйте `.env.example` в `.env`.
5. Задайте уникальные значения `SESSION_SECRET`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`.
   Пароль должен быть длинным и уникальным. Не используйте пароль из примера.
6. Запустите:
   `npm start`
7. Откройте витрину: `http://localhost:3000`
8. Откройте панель: `http://localhost:3000/admin`

При первом запуске администратор создаётся из переменных окружения. Учётная запись создаётся один раз. Если нужно сменить пароль после первоначальной настройки, обновите хеш в таблице admins с помощью безопасной административной процедуры или создайте отдельную процедуру сброса пароля; простое изменение `.env` существующую запись не перезапишет.

## Где хранятся данные
- `data/doma-tech.sqlite` — товары, заказы, администраторы.
- `data/sessions.sqlite` — серверные сессии.
- `uploads/` — загруженные изображения товаров.

Эти папки должны сохраняться между перезапусками и обновлениями приложения. Делайте регулярные резервные копии базы данных и папки uploads.

## Публикация
Размещайте на Node.js-хостинге или VPS, где можно запускать постоянный Node.js-процесс и подключить постоянное дисковое хранилище.
Для production:
- установите `NODE_ENV=production`;
- задайте `SESSION_SECRET` длиной не менее 32 случайных символов;
- задайте сильный `ADMIN_PASSWORD`;
- включите HTTPS;
- настройте постоянный диск для `data/` и `uploads/`;
- настройте резервное копирование;
- ограничьте доступ к серверу и регулярно обновляйте зависимости.

SQLite подходит для начального небольшого магазина с одним экземпляром приложения. При росте нагрузки или нескольких экземплярах сервера следует перейти на PostgreSQL и общее объектное хранилище для фотографий.

## Важные ограничения до реального запуска продаж
- Платёжный шлюз не подключён.
- Автоматическая доставка, складские остатки и интеграции поставщиков не подключены.
- Заявки сохраняются в БД, но уведомления на e-mail/мессенджер не настроены.
- Не добавляйте выдуманные модели, цены, наличие, отзывы и условия гарантии.
- До сбора реальных заявок опубликуйте юридически корректную политику обработки персональных данных и получите необходимые согласия.
- Добавьте реальные контакты, сведения о продавце, условия оплаты, доставки, возврата и гарантии.
- Проверьте требования законодательства РФ к обработке и хранению персональных данных и размещению баз данных до коммерческого запуска.

## Структура
- `server.js` — сервер и API.
- `public/` — витрина и интерфейс админ-панели.
- `data/` — SQLite базы (создаются автоматически).
- `uploads/` — изображения товаров.
- `.env.example` — пример конфигурации.
